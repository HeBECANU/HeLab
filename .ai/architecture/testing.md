## Running the suite

For the full suite, prefer the parallel form: `-n 12` runs 12 pytest-xdist workers (use at most the machine's CPU cores; CI uses `-n 4`). Never use `-n` without `--reruns` and `--reruns-delay` (pytest-rerunfailures): parallel workers can race (e.g. over temp folders) and Qt/timing tests fail now and then under load. Report any test that needed a `RERUN` rather than calling the run clean. Tests run Qt offscreen by default; set `HELAB_SHOW_GUI=1` to see the windows. `tests/conftest.py` gives every test's `tmp_path` a `.helab-root` and a fake volume ID (`temporary_data_root`); tests of RAM-only folders or of markers themselves opt out with `@pytest.mark.no_auto_data_root`. **Tests never touch real data** (Tony, 2026-10-20): conftest sets `HELAB_TEST_SOURCE_GUARD`, under which the helper (`helab/io_ops/infra.py`, `_guard`) refuses (`SourceRefused`, before touching it) any source path below `/Volumes`, `/Network`, `/net`, `/media`, `/mnt`, `/run/media` or `~/Library/CloudStorage`, a network or other-drive path on Windows, or inside `constants.DEV_POTENTIAL_DATA_PATHS`, unless it is inside the temp folder or this checkout; the refusal fails the test (`no_real_data`, `tests/test_real_data_guard.py`), and new tabs start in an empty temp folder. A test of mounts uses paths that don't exist. Production code reads these test seams: `HELAB_TEST_LOCAL_MOUNT` (Windows: one local mount), `HELAB_TEST_VOLUME_ID` (a fixed volume ID) and `HELAB_TEST_READ_GATE=<dir>` (`helab/io_ops/infra.py` only: a TXY read of `<name>` waits until `<dir>/<name>.go` exists, sending nothing meanwhile, so tests order reads on every platform and a gate never opened is a stuck read; `tests/test_live_io.py`) and `HELAB_TEST_IO_TRACE=<folder>` (`helab/io_ops/infra.py` only: every helper appends each source-folder operation to its own `<folder>/<pid>.jsonl`, as Help › Record I/O trace does; `tests/test_io_trace.py`) and `HELAB_REQUIRE_BACKENDS=cython,rust,…` (`tests/conftest.py`: a named converter backend that can't load stops the run, and a skip naming one fails; CI's converter-backends job sets it) and `HELAB_TEST_SETTINGS_FILE=<file.ini>` (`helab/utils/settings_store.py`: `app_settings()` opens that ini instead of the native store; `tests/conftest.py` gives every test its own) and `HELAB_UNITS_PLATFORM_OVERRIDE` (`number_format.PLATFORM`, read once at import: the platform whose byte units HeLab shows, `sys.platform` when unset; conftest pins `darwin`, so labels compare the same on every OS; test Windows' units with `platform="win32"`, by patching `number_format.PLATFORM` (call time), or in a fresh interpreter for what is set at import: the disk budget's default and minimum, `app_log.MB`, `test_units_set_at_import_follow_the_platform`; `HELAB_UNITS_PLATFORM_OVERRIDE=win32 helab` shows Windows' units on a Mac, and helpers inherit it). `tests/conftest.py` points the cache, temp and app folders at private temp folders (`HELAB_DIR_*_OVERRIDE`, `HELAB_APP_DIR_OVERRIDE`), which `helab.utils.constants` reads once at import: never import helab before pytest loads conftest (e.g. a script calling `pytest.main()` after its own helab imports; patch from a fixture instead). Conftest refuses to run then, since tests would write into the real cache. A script that imports helab outside pytest (a render or debug script) should set those three variables first too.

## Isolation, seams and fixtures

`pytest.ini` sets `pythonpath = .`, so pytest tests the checkout it runs in, whatever the venv's editable install or `PYTHONPATH` names (`tests/test_test_isolation.py`). Each test gets a disk cache store of its own (`private_store` in `tests/conftest.py`: `cache_dir()` and the helpers' `HELAB_DIR_CACHES_OVERRIDE`), so nothing a test saves reaches another. Before a test deletes a store through real helpers, it waits with `store_free(*services)` (`tests/conftest.py`) until neither its services nor the app-wide one has a cache helper running or unconfirmed. The app-wide IOService and FolderCache last a worker's run: real-window tests that change their state (Work Offline, quitting) restore it (`back_online`, `no_quitting_cache`), and a test may not assume no other service starts work during it. **Source runs driven by computer use (macOS):** `python dev/dev_app.py [--env-file .ai/local/floor-env.sh]` builds `.ai/local/HeLab-dev.app` (bundle ID `au.edu.anu.he-bec-lab.dev`, its own `--tag` for a second checkout); `open` it, never `venv/bin/helab`, and quit it before opening it again (`open` while it runs drops the new arguments; `open -n` makes a second instance with the same ID). With `floor-env.sh` the log is in the floor's app folder (`HELAB_APP_DIR_OVERRIDE`). **Accessible names** (`tests/test_accessible_names.py`): it opens each window and dialog (the main window with a synthetic folder, plots tabbed, released and floating; again with every script of every group and Counts per shot in each Library; Settings at each tab; eleven dialogs and tool windows; six message boxes HeLab builds, `ASKS`), walks every interactive control (`QAbstractButton`, `QComboBox`, `QLineEdit`, `QAbstractSpinBox`, `QAbstractSlider`, `QTabBar` and each tab, `QAbstractItemView`, editable text edits; less a control's own parts) and fails on any without a name or ID, or whose ID repeats among its window's shown controls. PyQt6 doesn't bind `QAccessible`, so `effective_name` follows Qt 6.11's rules. `test_every_widget_class_is_walked_or_skipped_with_a_reason` imports `helab/views`, `helab/analysis` and `helab/scripts` and fails on a `QWidget` subclass no case opens and `SKIPPED` doesn't list; `INLINE_SKIPPED` lists, with why, dialogs Qt builds itself. A new window or dialog: add a builder to `DIALOGS` (or a case with `@covers`); a new message box: an entry in `ASKS`. Window tests that load data but don't check caching use RAM-only folders (`no_auto_data_root`), so quitting never waits on a save. `tests/test_helper_events.py` reads the helper's side (`helab/io_ops/`, `io_helper.py`) and the app's (`helab/views` with its `plots` package, `helab/utils`, `helab/models`, `main.py` and the headless converter's `convert_cli.py`, less `NOT_GUI`) and fails on a kind sent but not declared or declared but not sent, a kind the app matches that nothing sends (`GUI_KINDS` aside), and one the app is sent but never matches (`RECEIPTS` aside); `NOT_EVENTS` lists helper dicts with a `kind` that aren't events. Deferred deletes are sent after every test, also when its teardown raises, and a test that leaves a `QWebEngineView` alive fails (one deleted later crashed Qt; `tests/test_left_widgets.py`). The summary prints "rerun reasons" (why each rerun failed): quote them when reporting a RERUN. In CI logs, rerunfailures sleeps `--reruns-delay` before it logs RERUN, so subtract it (5 s on CI) from a rerun's apparent duration. A worker "crashed" under xdist with no traceback is usually `--timeout` (CI: 120 s), whose stacks xdist drops: look for the faulthandler dump at 100 s (`faulthandler_timeout`, `pytest.ini`). An exception Qt raised from C, with no traceback, gets a note naming the code that was running Qt's event loop (`where_qt_raised`, `tests/conftest.py`), and a cache left quitting by a test is shut down before the next (`no_quitting_cache`). **store-v4's tests** turn the switch on with `switch_on` (`tests/test_store_v4.py`: the `store_v4` row in the test's ini plus `cache_store._reset_live_layout()`); the switch is read once per process, so a test that changes it resets the layout. `raw_fill`'s tests use `v4_live` (`tests/test_raw_fill.py`: `cache_store._reset_live_layout(4)`). `tests/test_caching_v2_session.py` is stage 1's switch-on integration check (one session through the app's own `store_options()`, beside an older HeLab's store-v3: load and `raw_fill`, layer equals file, Clear all, Make room through a real `cache_full`, a COPY cache move with both stores, `helab cache export --folder` after the raw files are gone); it watches `sqlite3.connect` and `CacheStore.__init__` for any open of store-v3 outside `LegacyStore` and hashes v3's files. `tests/test_cache_cli.py::test_helab_cache_starts_no_qt` runs `helab cache` in a subprocess and asserts no PyQt6 module loaded; `test_the_format_pages_reader_without_helab_reads_what_helab_writes` holds a copy of `docs/hlb-format.md`'s "without HeLab" reader, so a change to the page's sample goes into the test too. Offline tests (`tests/test_offline_browsing.py`) deny source access with `no_source_io` (no source operation reaches `IOService._start`) and `deny_source` (`os.scandir`, `stat`, `lstat`, `listdir` and `open` of the source tree fail the test); tests that call `set_offline` reset `folder_cache._offline`. pytest-qt's Qt log capture is off (`--no-qt-log`, `pytest.ini`): its per-test swap of Qt's message handler raced with QtWebEngine logging from another thread (Ubuntu teardown errors); Qt messages show in captured stderr.

**Caching v2 stage 2's tests** (landed `1cd586c`; the switch on in each, temp stores only): `tests/test_txy_layers_store.py` (the store side: segments, per-shot job order, views, the pending merge, compaction, the five-group planner and `trim`'s plan, Clear, the sweep over `txy/`, S2-0's rekey, the migration), `test_txy_loading.py` (the loading order, every source mode, the folder's choices, A40.3, the seeds, A42.1, a HeLab shot from the raw layer, Live's segments and compaction), `test_txy_fixes.py` (S3-1, S3-2, the purge's estimate), `test_txy_ui.py` (Settings › Cache's rows, the policy, the plan-based budget question, Make room's text and items), `test_cache_cli.py` (`--kind txy`, the recorded cache folder) and `test_cache_folder_record.py` (only the GUI writes `cache-folder.json`); `test_caching_v2_session.py::test_a_stage_2_session_with_layers_leaves_store_v3_as_it_was` is the integration check (conversion → loads from the raw layer and layers → a plot's own choice → ten Live autosaves compacting → Clear all → Make room through a real `cache_full` → store-v3 hashed unchanged → a cache move and `helab cache export --kind txy`).

**Settle time and destroyed signals** (`agent/ui-polish`, landed `c104502`): `tests/test_settle_setting.py` checks that every helper route runs with the request's `settle_seconds`; `HELAB_SETTLE_SECONDS` (conftest's 0) wins over the request, so tests that need the request's value patch `fingerprints._SETTLE_OVERRIDE`. `tests/test_destroyed_connections.py` is an AST guard (no `.destroyed.connect(` to anything but a bound method in `helab/`, including `connect(slot=…)`, `destroyed[QObject]` and a signal stored in a name first) plus a closed Plotly plot's figure leaving `dash_server` at once. A test that waits for a close to free something never calls `gc.collect()` in its wait: it would hide a release that only a collection makes. Sibling test modules are imported by bare name (`from test_x import …`), never `tests.test_x` (mypy sees the file twice). `test_user_tags.py`'s deep-path test runs only its "converts" branch on GitHub's Windows runners (long paths on); the "too long" branch is covered by the patched tests.

## Windows

Windows: if pytest crashes during cleanup with `WinError 5` for
`pytest-current`, use either option in PowerShell:

```powershell
pytest --basetemp="$env:TEMP/helab-pytest-fresh"
pytest --basetemp=.ai/temp/pytest-fresh
```

Use a dedicated scratch directory per concurrent run: pytest clears it at startup.

## Sample data and opt-in tests

`tests_sample_data/` (tracked, 12 MB, 43 files) holds a few shots from the lab: `goodish/` (`d<N>.txt` and `d_txy_forc<N>.txt` pairs 1–10 with the run's two MATLAB logs), `bad/` (pairs with gaps) and `bad_txy/` (shot 256). It is inside the checkout, so the source guard allows it (`tests/test_real_data_guard.py`), and it is one of `constants.DEV_POTENTIAL_DATA_PATHS`. `tests/test_convert_reference.py` reproduces its raw/TXY pairs byte for byte, so the folder has a `.gitattributes` `* -text`, as `tests/data/convert/` (the converter's fixtures, also compared byte for byte) does: Windows CI's autocrlf would otherwise rewrite the LF TXY files (a guard test checks they have no CR). `tests/test_windows_paths.py` fails on any tracked path Windows can't check out (reserved names such as `nul.txt`, `<>:"|?*`, a trailing dot or space): one such file once stopped every Windows CI job at checkout. Two opt-in tests are skipped unless set: `HELAB_TEST_NATIVE_ICONS` (macOS native folder and volume icons, `tests/test_folder_icons.py`) and `HELAB_TEST_REAL_VOLUME=1` (this machine's volume IDs, `tests/test_data_roots.py`).

**HeLab's test data** (Q31.4) is the private Hugging Face dataset `TonyXTYan/HeLab-TestData`, built
by its `tools/build.py` from the local sample copies (`~/GitHub-Local/HeLab-testdata` on Tony's Mac):
a few raw/TXY pairs per detector era, Live, raw-only, TXY-only, nested and damaged folders, and
`reference/matlab-2023` (the only 2023-variant MATLAB output, M11.3), every file in its
`manifest.json` with its SHA-256. Tests pin a tag (`v1`; a change is a new tag). CI's
`.github/actions/testdata` downloads it with the `HF_TOKEN` secret (a read-only token), cached per
OS, and sets `HELAB_TESTDATA` and `HELAB_REQUIRE_TESTDATA=1`; without the token (forks, the lab's copy)
the tests that need it skip. Locally it is the `testdata` submodule, pinned at the tag's commit and never
fetched by default (`update = none`: `git submodule update --init --checkout testdata`, with HF's git
credentials), or a download anywhere named by `HELAB_TESTDATA`, which wins. On Tony's Mac,
`~/GitHub-Local/HeLab-testdata` is a symlink to the submodule (git refuses a symlink at a submodule's path).
A new tag: upload, tag, then move the submodule and the action's `--revision` together. `tests/test_convert_testdata.py` checks the
manifest and converts every pair byte for byte (`matlab-2019` on the eras, with its listed archive
faults; `matlab-2023-lab-edit` on the reference), by numpy and, in the Converter backends job,
cython. Tests only read it; one that writes copies it into its temp folder first.

## Slow tests first

Slow tests first (Quick Fixes 6, 2026-10-29): `tests/conftest.py`'s `pytest_collection_modifyitems` puts the modules in `SLOW_FIRST_MODULES` (today `tests/test_typing.py`) at the start of each xdist worker's first batch (`slow_first_positions`, which mirrors xdist's `LoadScheduling` first batches), so they overlap the suite instead of forming a serial tail; a new module as slow belongs in that list. Each mypy test there has its own `--cache-dir` (`.mypy_cache/test_typing/<name>`, ignored), because concurrent mypy runs sharing one SQLite cache crash. `--test-group N/M` runs one group of the suite (CI: two per OS, A17.2): a test's group is `zlib.crc32(nodeid) % M + 1`, the `SLOW_FIRST_MODULES` tests dealt out in turn and still first inside their group; `config.stash[ALL_TESTS]` keeps the whole collection, which `tests/test_test_groups.py` checks splits once. Two traps (Quick Fixes 4, 2026-10-29): patch process-wide functions (`os.scandir`, …) only for the test's own thread, since `IOService.release` runs `shutil.rmtree` on a daemon thread (`HeLab-artifact-cleanup`): wrap a fake that refuses or records every call, or replaces `Popen`, in `conftest.this_tests(fake, real)` (A46.1, `6fa8cd9`: the test's thread and every thread started after the patch get the fake, threads alive before it the real one, compared by thread object; `test_test_isolation.py`), and a `Popen` fake that must see only its own request's start matches that request's stderr path through `IOService.before_start` (A40.1's guard test, `d480a82`), since another IOService's helper thread starts after the patch too; and don't `chdir` while helpers can start: they inherit the working folder, which the source guard denies outside the temp folder and the checkout (it shows only with `--basetemp` outside the checkout, so run the suite that way now and then). A path with spaces in the temp folder also catches tests that split paths on whitespace.

**Their own timeouts** (Quick Fixes 9): CI runs with `--timeout=120 --timeout-method=thread`, which kills the xdist worker. `tests/test_typing.py` (a module-level `pytest.mark.timeout(300)`, `e8a28a1`) and `test_accessible_names.py::test_every_script_and_each_library` (`pytest.mark.timeout(300)`, `5f52068`; one walk, not split per library) get 300 s, each with a guard test, after a slow macOS runner killed them at 120 s (caching-v2 CI 41389534725: pyright 115–142 s there, against 40–97 s usually; the walk 123 s). A test that runs that long gets its own mark rather than a raised global limit.

**GUI stalled lines in CI logs** (Quick Fixes 9): `GUIWatchdog`'s thread ends once its QObject is deleted (`36b2224`, A47.3; `tests/test_gui_watchdog.py`), and its line reads `GUI stalled for Xs (<window class> ['<objectName>']; made in <test>; now in <test>); capturing thread stacks` (`1bc8020`; the tests from `PYTEST_CURRENT_TEST`). **A "GUI stalled" line whose made-in equals now-in is that test blocking the GUI thread with its own window, not a leak** (Windows CI shows a few per run, e.g. the accessible-names walk, up to 28 s); `test_gui_watchdog.py`'s deliberate stall (`plots_window`, ~10 s) shows too. Lines from other workers interleave in the log.

**Tests of tonight's floors** (2026-11-03): `tests/test_share_detection.py` (`share_of` on made-up mount tables and paths that don't exist, `os.path.realpath` refused in the lexical tests; the Windows mapped-drive case runs on Windows CI; an AST check that no `helab/` module imports `share_of` or `mount_table` by value) and `tests/test_explorer_convert.py` (Folder details' offer, the share and Q38.1 questions; the app and CLI tests patch `cache_location.share_of` and assert the GUI never asked with `resolve=True`). `test_live.replay`/`run_helper` run a load without its `txy` field, so a test of HeLab TXY loads runs the load itself (`test_explorer_convert.load_as_the_helper_does`; A48.1). Live scripts: `tests/test_scripts_reload.py`, `test_live_scripts.py` and `test_plot_txy_saved.py`, all with temporary script folders and in-memory datasets; `test_scripts_reload.imports_restored()` restores `sys.path`, `sys.modules`, `sys.path_hooks`, `sys.path_importer_cache` and `_SOURCE_ONLY` after each test. Caching v2: `test_txy_fixes.py` (each kind's purge takes only its kind, keeps only copies and frees exactly its estimate; `all`; unknown purges refused) and `test_txy_ui.py` (the per-kind rows and questions, Everything with and without its box; A47.2's listing feeding FolderCache), `tests/test_convert_on_read.py` (stage 3: on-read loads, Live, A40.2, a stalled read sending no heartbeat, the counts by source), `test_txy_only_offer.py` (S4-1), and `test_caching_v2_session.py`'s stage 3 session (a load converts on read; a user profile converts from the raw layer without reading a raw file; Live converts a new shot while an unfinished one waits; Clear all; store-v3 unchanged and opened only by `LegacyStore`). `test_io_trace.py::test_the_gui_process_never_touches_source_folders` waits up to `HELPERS_MS` (60 s) for its helpers (`ee4994b`; it takes 9–18 s on Windows runners); other tests' `wait_idle` keep 20 s.

## Disabled tests

Tests ending in `.disabled` are intentionally skipped (not collected) — don't try to "fix" them into passing without checking why they were disabled first.
