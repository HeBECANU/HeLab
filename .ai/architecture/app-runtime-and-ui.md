## Logging

**One HeLab app per computer** (Q39.1, A39.3, `0335768`): `main._another_running()`, right after `QApplication(argv)` and before the style, icons, `_start_cache`, helpers, the window and `app_settings`, takes `running.lock` in the app folder (`cache_locks.take_running`, an OS file lock with the pid in it); held, HeLab says "HeLab is already running on this computer (process N)…" and exits 1; the lock is held until the process ends, so a new start waits for the old one's saves; a dead process holds no lock whatever pid the file names; an app folder where it can't be checked is logged and HeLab starts. `HELAB_APP_DIR_OVERRIDE` gives agents and tests their own; `helab convert` is dispatched before `main()` and doesn't take it (Q43.2), nor does `helab --help` (A56.7: a short usage, exit 0, before Qt, settings, caches and Dash; [release-and-ci](release-and-ci.md)). The log starts before the check, so a refused start leaves one line in its own log file. Each HeLab logs to its own `<app folder>/logs/helab-<pid>.log` (INFO and up, rotated at 1 MB, 10 older files; macOS `~/Library/Caches/HeLab/logs/`, Windows `%LOCALAPPDATA%\HeLab\logs\`; Help › Show log folder). An unhandled exception, on any thread, is logged with its traceback and HeLab carries on, with a status-bar note "Unexpected error, logged: …"; the same one is logged at most once a minute, its repeats counted (`helab/utils/app_log.py`, started first in `main()`). A source file dated more than 2 s ahead of this PC's clock makes helpers send `clock_skew`: HeLab says the computers' clocks are out of sync, once per share or volume per session (`ClockSkewWarning`), and Live on that folder stops like an error stop. At startup, off the GUI thread (`helab/views/OldLogs.py`), HeLab deletes the oldest log files by mtime beyond Settings → General → Log files to keep (default 300, every session's files and rotated copies counted); past 50 MB left it asks once per session "Log files use X MB. Delete old ones?" (Keep the default, for the session; Delete goes under 20 MB). Never a running HeLab's files (live instance locks, this pid) or one modified in the last minute; one that can't be deleted is skipped and logged (`app_log.tidy_logs`, `trim_logs`). **Milestones** (`agent/runner-tools`, landed `0316bae`): when a folder's load, a plot's compute or a conversion ends, HeLab logs one INFO line on `helab.milestone`, `MILESTONE <event> key=value …` (`app_log.milestone` writes every one, `parse_milestone` reads it back): `load_done` (`folder shots events seconds source=cache|folder|check|save live`, from `FolderCache`), `plot_done` (`script version action plot job seconds state=ok|failed|cancelled`, from `AnalysisRunner`), `convert_done` (`folder by=live|cli converted no_hit unconvertible waiting kept output seconds`, Live auto-convert and `helab convert`; not for a run that changed nothing). `no_hit` differs slightly: Live counts the growth of its no-hit set (a failed run's no-hit shots carry into its next line), `helab convert` counts every no-hit conversion of that run (a stale shot converted again included). A runner (the smoke pass) waits on them in the log file; the only path in them is the folder.
**After a crash** (LR-15, `733a5c7`): `logs/crash-<pid>.txt` (faulthandler, all threads, kept open, removed empty at a clean exit) and each helper's `helper-crash-<pid>.txt` (standard library only, its folder from IOService's environment; `helab/utils/crash_file.py`); `console-<pid>.txt`, an fd-level tee of stdout and stderr rotated once at 20 MB (`helab/utils/console_tee.py`; each pump writes the file first and hands the terminal its copy on the terminal's own thread, `_Terminal`, dropping what a terminal that takes nothing can't hold, so a paused console never fills the pipe; on Windows a console's `sys.stdout`/`sys.stderr`, which write to the console's handle past the descriptor, are pointed at the new descriptors with the logging handlers holding them, `writes_past_its_descriptor`; off under pytest, `HELAB_NO_CONSOLE_FILE` from conftest; helpers' stderr stays per request); Qt's warnings and criticals in the log with their category, once a minute per message (`app_log.install_qt_messages`), and Python warnings captured; a memory line a minute while Live is on (`HelabMainWindow.log_memory`); the previous run's crash named at start. The startup tidy prunes crash and console files with the logs, and empty ones always. Not yet tried on Windows, where a child process's output may not reach the console file.


## Threading

**Threading:** The GUI process has no worker pools, except the single analysis worker thread (`AnalysisRunner`), which computes analyses and never does source I/O, and the short-lived startup thread that tidies old log files (`OldLogs`). Source-folder and disk-cache work runs in isolated `io_helper` processes, whose results daemon reader threads deliver (see Responsive filesystem I/O). `GUIWatchdog` and the Dash server run on their own background threads, and `io_service.py` starts short daemon threads (`HeLab-artifact-cleanup`, `HeLab-cancel`).

## Window resizing

**Window resizing:** Keep Qt's normal main-window resize and repaint handling. Disabling updates for the whole window during resize and restoring them with a timer can stop paint delivery while I/O continues. Resize regressions in `tests/test_window_resize.py` check continuing paint events and scan cancellation, not just `updatesEnabled()`.

## `FolderCache` memory and the RAM budget

The active browser additionally uses session-only `FolderCache` (`helab/utils/folder_cache.py`), shared by models using the same IOService. Completed directory snapshots have a 10-second freshness window; explicit refresh bypasses it. Shared scan/load/resolve jobs have per-tab subscriptions, so closing one tab does not cancel another's work. Datasets share read-only NumPy arrays with private dictionaries per tab; analysis code that intentionally modifies an array must call `.copy()`. The RAM budget (Settings → Cache, steps of 1/128 of RAM, default 1/8; `FolderCache.set_ram_budget`) evicts datasets no tab shows, least recently used first, while open tabs pin their current datasets. Plots count too (`helab/analysis/budget.py`, `RamBudget`; its Qt-free parts, the shares, `hollow` and `restore`, in `budget_core.py`): each plot's view, its result arrays (every result `RamResults` keeps for it) and a released plot's PNG picture, by buffer (`helab/utils/ram_buffers.py`), so arrays shared with a held dataset or another plot count once (`FolderCache.plot_bytes`); eviction keeps a dataset whose arrays plots hold anyway. From 50 % of the budget the status bar shows it; at 75 % a non-modal window lists the biggest plots and folders (once per crossing, re-armed below 70 %); above 80 % datasets no tab shows go first (`evict_to`, again after each release), then plots are released, least recently shown first (one reloaded in the last 10 s last), in two passes (first only plots that free more than their picture with every other plot staying), until under 80 % (never the shown, a running or a Live-following plot; none closed). A released plot shows its PNG picture with Reload and keeps a hollow view (its shots' numbers and fingerprints); it reloads from RAM or a local `cached` read only, never its folder, exactly the shots it drew by fingerprint, naming changed or missing ones, when it becomes the shown plot (Settings → Cache, `plot_auto_reload`, default on; not again after finding nothing until its folder's data or disk cache changes) or on Reload. Directory snapshots are bounded to 256 folders and 100,000 retained entries. This memory store supplements the compressed disk cache and **never reads disk during rendering**.

## UI

**UI:** Model-View pattern. The active `FolderExplorer` uses `SnapshotFileSystemModel` (`helab/models/SnapshotFileSystemModel.py`), a `QAbstractItemModel` that only reads memory during rendering — badges, tooltips, summaries and relative ages must never touch the source filesystem, the disk cache, or submit I/O. Directory contents are scanned on selection or expansion; an unlisted folder whose saved summary has no subfolders (`has_dirs`) shows no expand arrow until selecting it (or a load's listing) finds some; automatic basic scanning of visible folders is off by default and never rescans folders with saved results. Freshness indicators are hints only and never schedule scans or loads. Navigation and direct path entry stay available during I/O. A folder's status as the browser shows it is a `StatusReport` (`helab/models/StatusReport.py`, plain data); freshness hints come from `helab/utils/cache_freshness.py`, and shared labels from `number_format.py` (byte sizes by kind and OS, Q26.1; the status bar's RAM in GiB), `time_format.py` and `helab/views/explorer_text.py`, all memory only. The folder summary panel, cache-freshness icons and their wording are described in `.ai/memory/results/folder-summary-indicators.md`. The main window (`helab/views/HelabMainWindow.py`; folder tabs in `FolderTabWidget.py`, the Settings window and its tabs in `SettingsDialog.py`) uses dockable panels: left tree view with **Folder details** (`helab/views/FolderDetailsPanel.py`) below it, right properties panel, center plot area. Quit: `closeEvent` → `_wait_for_saves` (Live off, the converted TXY's last-uses flush, the quit window listing every pending operation; [live](live.md)), then `quit_watch` ends the process within 1 s.

**The Activity window** (Q62.1–Q62.5; `agent/activity-window`, landed `5af4a89`; manual: "See and manage
what HeLab is doing"): Window › Activity (`window_activity`) and a click on the status bar's message
(`status_activity`, its tooltip's last line "Click for Activity", `HelabMainWindow.ACTIVITY_HINT`;
`ActivityWindow.ClickOpens`) open one non-modal `ActivityWindow` per main window, built hidden at start.
Its model is Qt-free (`helab/utils/activity.py`, in `PURE`): `Task` rows in a `Snapshot`, built from memory
only by `ActivitySources` (`helab/views/ActivityWindow.py`) from IOService's `active`, `pending` and
`retired` (a retry held behind its stopping attempt is one row), FolderCache (`job_of`, `admin_action`,
`finishing_of`, `raw_filling`, `quit_entries`' waiting and held saves), each tab's Live sessions
(`LiveController.sessions`) with their checks, saves and auto-convert under them, GUI conversions and the
converter's open questions, the analysis runners (`AnalysisQueue.jobs`, `RunInfo`), the Scripts panel's
test imports and a waiting reload, and the cache move. Groups: Loads and scans, Saves, Live, Conversions,
Cache upkeep, Analysis, Scripts (Other for anything new). States: running, queued (its place, or why
held), paused (by the foreground, the mismatch hold or the user), stopping (until the exit flag), waiting
for N files to settle, no progress for M:SS (`LoadClock.STALL_SECONDS`), failed. Its counts are
`activity_counts`'. **Hidden, it does nothing** (no timer, no connection); shown, a 200 ms coalesced
refresh on `activityChanged`, terminal `resultReady` kinds, `quitSavesChanged`, runners' `finished` and
history appends, plus a 1 s tick; rows update in place. **Actions go through each owner's own path**
(`ActivityActions`): Cancel (a tab's selected load through `cancel_loading`, the toolbar's Cancel, which
also stops that tab's background loads, as its tooltip and the manual say (CoCo, AW-3); else
`FolderCache.cancel`, auto-convert's toggle, `cancel_raw_fill`, `CacheMover.cancel`,
`AnalysisRunner.cancel`; saves, cache upkeep and test imports have none), Retry (`resume_live`, the Convert row's `clicked`, `refresh_folder`, `FolderExplorer.retry`,
a plot's `run`, `reload_scripts`; refused while `IOService.unexited(operation, path)`), Show in tab, Stop
Live, Open log (this session's log file), Pause / Resume background I/O (`IOService.set_user_hold`) and
Cancel all queued (never a running task: a tab's selected load is left to its tab's Cancel,
`cancel(…, queued_only=True)`; saves stay). **The Now tree** fills rows in place; when any row's group or
