# Live monitoring

Reference detail for agents working in this area. It moved here verbatim from `AGENTS.md` on
2026-10-28, when AGENTS.md was cut to rules and a map ([index](README.md)). AGENTS.md keeps the
rules every task must follow; this file keeps the mechanics, names and behaviour. Keep it true:
on Ground, update it in the same commit as the code; on a floor, propose the change in your handoff. Settled decisions and Tony's wording live in
`.ai/memory/results/`; feature plans in `roadmaps/`.

## Live

**Live** (`roadmaps/live-monitoring.md`): the toolbar's Live watches the current tab's selected folder once its data is shown (`FolderExplorer.start_live`; `LiveController` and `LiveSession` in `helab/views/explorer_live.py`, the tab's `live_control`); the tab's tree, path bar, Deselect, Up, Refresh and Check folder status are locked, and the summary's third line shows Live's state. A check is a `load` with `live` in its payload (`io_ops.live.live_check`, owner `<tab>:live`, foreground lane): one folder stat while the folder's mtime equals the last safe one (not within `fingerprints.RACY_SECONDS` = 2 s, the one constant the quick check and Live share, no files still being written, listed at least once a minute: `listed_at` moves only for a check's own listing, `live_listed`, never a save's), else a names-only listing. On a listing, held shots are reused only if the folder's identity (nearest `.helab-root`, else its location) is the one Live's first listing found and the check level's sample of held shots keeps its (size, mtime); otherwise `shots_missing` (`reason` root or changed) stops Live and lists the folder as mismatched, except for a held shot Live itself read in the last 5 minutes (`LiveSession.read_at`, `LiveController.LIVE_REREAD_SECONDS`, sent as `recent`): when it changes, it is read again like a new file and replaces the held one (`live_reread`), by Tony's decision; the Live line and Folder details say "Shot N changed after it was read (writer paused > 5 s?): read again" for a minute, and one WARNING per shot logs its path, old and new (size, mtime) and the seconds since Live read it (within that window such a shot is guarded by the missing-file and identity checks, and every listing stats it besides the check level's sample, so a writer resuming it after a newer shot arrived is still seen: Codex review on PR #9). While the folder's mtime is the last listing's, a check stats only pending files; the identity reads the known root's marker. A new file is read only when settled by age and unchanged since the previous check (`seen`): metadata only, by Tony's decision; its content isn't checked. A writer paused longer than the settle age is read unfinished; the converter writing to a temporary name and renaming it remains the real fix. Results: `live_unchanged`, or `loaded` with `memory_shots` (source `updated`). Checks have their own job key (`("live", path)`). The next check starts `live_interval` after one ends (Settings → General, 3 s). New shots stay in RAM; every `live_autosave_shots` (Settings → Cache, 10) and when Live stops (Live off, another folder, tab switch or close, quit) a background save writes the folder from RAM (`FolderCache.save` → `io_ops.save_held.save_held`: one listing, every held file checked by its stats, no TXY read; a recent changed shot is read again first; it always sends its folder summary (`scan_summary`) before `loaded`, adopted only if not older than the folder's snapshot, so a newer listing elsewhere keeps its own status and the save's data isn't counted as checked (`behind_listing`; io-3); a held shot with no data (found unreadable) is treated as a Live check treats it: read again once settled if it changed, dropped if gone, never a mismatch (io-4); a held HeLab shot whose TXY has gone is saved as held and counts as unsettled, named as its beside TXY would be, and the saved dataset carries the signature `loaded` sent, `folder_print`'s: Quick Fixes 7, Codex on PR #10, `4222b3f`, `a7dac90`); a held shot keeps its kind in checks and saves while that TXY is there, held from MATLAB's too (`fefe6ab`); under HeLab priority a shot held from MATLAB's TXY switches to the HeLab TXY converted for it during Live, read again like a changed shot once settled and seen unchanged a check apart (`helab_rereads`), its MATLAB TXY feeding the mismatch rule until then, so never a mismatch (A39.2, Q38.2; `10a9c3c`); a re-read caused by a new HeLab TXY (that switch, or a HeLab-held shot converted again) is marked `converted` in `live_reread` and logged at INFO, with no note on the Live line; a save never joins another load of the folder that isn't one, and saves of one folder never overlap (`_deferred_saves`); they obey the budget, Don't cache and pending-save rules. Errors stop the checks but keep Live and the data (amber line, Retry); nothing retries by itself. A shot that can't be written for the app (`infra._save_artifact`, e.g. a full local disk) is such an error (`ArtifactWriteFailed`; in loads and saves too), never an unreadable source shot, which would be kept known and not read again (Codex review on PR #9). Quitting turns Live off and waits for every operation `FolderCache.quit_entries()` lists (a typed `QuitSave(kind, path, state, started)` each; `quit_saves()`, the folders as strings, is derived from it): Live's new shots, a load's save, folder flags, constants, a plot's result or Make room for one, presets, the converted TXY's last uses loads skipped (Q30.3: `FolderCache.flush_txy_marks` just before, one `cache_admin` `mark_used` helper only when one was skipped, `TXY_LAST_USED`, a 5 s no-progress limit `MARK_FLUSH_TIMEOUT`, best effort, once) and a conversion still running (its shot finishes, Q34.4). `QuitSaveDialog` shows each as `<folder> — <kind>, <state> · <m:ss>`, updated in place from memory, closes by itself when they end, with Quit now; the process then ends within 1 s of the event loop (`helab/views/quit_watch.py`: past that it logs every thread's stack and exits with the same code); meanwhile no other folder work starts (`FolderCache.quitting`). Live never survives a restart. Live may start on any folder this session listed with no TXY files (it reads only the folder's own files, never its subfolders'): the tab shows data with no shots (`FolderCache.empty_dataset`, pinned), the first check lists the folder (`memory=[]`) and the line says "waiting for the first shot".

**Live with TXY layers** (caching v2 stage 2, store-v4 only, switch off; landed `1cd586c`; [cache-store](cache-store.md#txy-layers-stage-2)): each Live autosave (`save_held` through `txy_cache.Access`) writes one segment per layer of only the shots its layers lack or hold under another key, then the view (Q45.7); after any saved unit, each layer it wrote that is due (more than 8 segments, or more than half its bytes superseded) is compacted in the same job (`Access.compact` → `CacheStore.compact_txy`), only if the rewrite fits beside the old segments, else at a later save, never asking; under the converter's ticker. Live checks don't open the store, so Live follows a folder's own TXY source (Q45.2) through `FolderCache` (`with_txy`); since A47.2 (`28d2112`, landed `1d91897`) `FolderCache` learns a folder's choices with its listing (`metadata._read_saved` reads `read_folder_choices` beside the prefs: the folder's own go out as a `folder_choices` event, each child's in its entry's `choices`), so Live and a first load follow a folder's own source at once (Q47.2). `remember_choices` keeps each part (the policy; the source with its tag) by its own set time and emits `folderPrefsChanged` only on a change; a root's change of identity drops its folders' choices (`_root_prefs_gone`, A47-1).

**Live converts on read** (caching v2 stage 3, `4e86094`, landed `d4f28f3`; store-v4 only, switch off; Q50.6): with a source that reads HeLab's TXY, `with_txy` sets `on_read` on Live checks, and `live_check` takes new shots without a current HeLab text as on-read candidates as a load does, converting them with `txy_cache.convert_raw_file` whatever Auto-convert says; Auto-convert then also writes the text, which its store-v4 tooltip says ("Live converts new shots when it reads them; this also writes HeLab's TXY text to <destination>"; the label stays "Auto-convert", Q50.2). A held on-read shot isn't read again when a text of its profile appears (Auto-convert's): the data is the same by contract. Under HeLab priority Live converts only shots MATLAB's TXY lacks (Q50.1's option (a), `ced04aa`), and a shot it converted on read stays HeLab's when MATLAB's TXY of it appears: Live passes its held origins to `on_read` (`held`), which spares shots held from HeLab as `could_take` does (SQ-1, `9be3e12`). Live's held on-read shots are named in the dataset's `txy` record (`on_read`). **A40.2** (`4e86094`): a held HeLab shot whose new TXY turns out unreadable keeps its held data; the file goes back to the app as `live_failed`, and `LiveSession.held_failed` sends it with `known`, so it isn't read again while unchanged; a readable TXY then replaces the held data.

## Plots following Live

Plots follow Live (L3): the main window publishes each dataset a Live tab shows to its plot area's `live_feed` (`PlotWorkspace.follow_live`; `LiveFeed`, `helab/analysis/live_feed.py`), `revise` makes it the next revision of the folder's view (a dataset that isn't one, another load, TXY choice or profile, or shots gone, starts another chain, `ViewIdentity.chain`, which its plots run on once whatever their revision and Rerun every N; plots-1), and each plot of that folder reruns on the newest revision as its Live settings allow (`helab/analysis/follow.py`: `Follow`, `LivePolicy`); when Live stops (Live off, another tab, an error), plots holding shots back catch up once, at once, and a following plot whose last Live run skipped work (`rerun_after_live`: a bootstrap) runs once more on it. A load that reuses another dataset's arrays drops the folder's older datasets no tab shows (`_drop_superseded`).

## Notifications

Events worth telling someone about (a low-count shot during Live, from Shot trends' Notify during Live; Live stopping on an error, `LiveController._live_halt`) go through `helab/utils/events.py` and nothing else (`events.notify`, GUI thread): hooks attach with `events.hub().add_hook` and get every event (`Event.shown` says whether it was shown); a desktop notification (`QSystemTrayIcon.showMessage`, else the status bar and the log) is asked per event, delivered once per key (once per shot), with no time limit (Tony, 2026-10-26: a shot takes about 30 s). `notify(…, status=True)` without `desktop` shows the message in the main window's status bar for 10 s instead (its status sink, `show_status_notice`), records the event as shown and never notifies the desktop; a failing sink is logged (caching v2 stage 4's `RAW_KEPT`, S4R-1). With store-v4 live (caching v2, switch off; checkpoint 3, landed `c2d0ece`), Live's saves, like loads, schedule `raw_fill` for the folder, and a raw file overwritten in place since it was cached (by `raw_fill` or an auto-convert) notifies once per shot per session (`events.RAW_OVERWRITTEN`, Q28.6), with a log warning and Folder details' amber Problems line ([cache-store](cache-store.md#store-v4-caching-v2-behind-the-switch)).

## Auto-convert

**Auto-convert** (TXY converter stage 4, Q6.8; `agent/txy-live`, landed `6454b4a`; `AutoConvert` in `explorer_live.py`): the Live line's Auto-convert button ("Auto-convert" while Live watches the selected folder; before Live starts it reads "Arm auto-convert" (`explorer_live.ARM_AUTO_CONVERT`) and arms the selected folder, i.e. adds it to `FolderCache.auto_convert`, so Live started there converts at once (Tony, 2026-11-03); the sidebar toolbar's Auto-convert below Live (`action_tab_auto_convert`, the same menu on the arrow below it) mirrors it, so it stays at hand while Live collapses the left panel; its menu: Write TXY beside the raw files… (asked first), Start Live and auto-convert here when HeLab launches, Notify below N hits…) makes each Live tick also ask for `FolderCache.convert` (owner `<tab>:live`, operation `convert`, background lane): one per folder, at least `live_interval` after the last ended, each sending the last `convert_summary`'s lists back (`seen`/`done`/`kept`/`skip`; `done`/`kept`/`skip` only for the same profile, and under another `seen` without its reasons: a file waiting or unconvertible under one profile is read again under the next, its damaged notification not repeated; Quick Fixes 7, Codex on PR #10, `d5da485`, `d9a154d`). It converts with the conversion profile and backend (Settings → TXY converter). On is kept for the session per folder (`FolderCache.auto_convert`, Q9.6). A converted shot asks for Live's next check (`LiveSession.check_soon`), which reads it through the TXY source rules ([converter](converter.md)); one with fewer hits than `convert_low_hits` ([settings](settings.md)) notifies once per shot and raw file (`events.LOW_COUNTS`, `source="convert"`). A conversion's error (or Work Offline's refusal) stops auto-convert, not Live: amber line, Retry. The Live line and Folder details' Auto-convert row say converting N, converted K (last shot), waiting (no final newline, off trigger, future, unreadable) and unconvertible, reasons in the tooltip (kept across auto-convert off and on, `FolderCache.convert_reasons`). **A read stopped early** (A37.1, `fd43431`, Converter UX, landed `ed7bcf9`): `AutoConvert.stopped` keeps the files whose `shot_converted.read_stop` is set (by name, dropped when a file converts again to its end); the line says `d3.txt read stopped at line 1010` for one and `N reads stopped early` for several, amber, the tooltip lists each with `ReadStop.detail()`, and each file logs one warning; Folder details' Auto-convert row reuses `convert_line` and turns amber (`explorer_live.READ_STOPPED`; Q48.1). **Shares and refused beside writes** (A39.5, Q38.1; [converter](converter.md#shares-a395)): when the folder's beside flag is on and the folder is on a share not confirmed this session, nothing converts while a non-modal question asks (beside on the share, HeLab's cache instead, or auto-convert off); a beside write refused for want of a safe rename asks Retry, HeLab's cache or temp folder instead, or Not now. Both questions are closed and cleared with auto-convert (`_convert_off`, so `stop_live` too), and while one is open `_convert_tick` waits. A cache or temp choice is the folder's for the session (`explorer_convert.instead`, also read by Folder details' conversion; the beside flag unchanged), and the tooltip then says "This session: TXY go to HeLab's cache folder instead of beside the raw files".

**TXY lists in Live** (Q53.2, Q55.2; `agent/txy-priority`, landed `9bf99ff`; [converter](converter.md#txy-priority-lists)): Live reads with its folder's list (the folder's own, else Settings'), and its checks and saves compose by the list's chain ([io-and-browsing](io-and-browsing.md#loads-with-txy-layers)). Auto-convert converts with `FolderCache.auto_convert_profile`: Settings' conversion profile, or, after Live's offer, a one-entry list's profile. The offer (Q55.2): a folder whose list is one profile that Auto-convert doesn't convert with says "not read here: convert with m23v1?" on the Live line, and the menu has "Convert with m23v1 (this folder reads m23v1 only)" (`auto_convert_offer`, `set_convert_with`); taken, it holds for the session only while the folder reads that one profile (`taken_convert_with`; `set_folder_list` drops it; TP-7). Live's tick waits while a conversion of another profile runs on the folder (`converting_with(path, profile)` compares the whole profile, so a same-name profile edited meanwhile waits too; TP-5, TP-11).

## At launch

**At launch** (`helab/views/live_launch.py`, from the main window 10 ms in, `_open_first_tab`; Q18.3, `c718c71`): one launch folder (`live_launch_folder`, [settings](settings.md)), opened as the only tab, set to auto-convert, and Live starts once its data shows or it has no shots yet (`LaunchFolder`, as `PresetFolder`); later tabs work normally; a folder that can't be listed or started notifies once, no retry; working offline its tab opens without Live and a notification says so; never under pytest unless a test asks. Live on collapses the left panel (tabs, summary, Live line, Folder details; Q23.2) and Live off or an error restores it (a panel the user collapsed stays so). The Live line and Folder details also say "N damaged" (one notification per file, Q18.5) and "N shots with no hits" (amber, numbers in the tooltip, also for a folder shown later; A17.1, Q23.5).
